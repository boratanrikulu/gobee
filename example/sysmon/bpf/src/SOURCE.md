# Vendored: `vmlinux.h`

The kernel BTF dump used by the example's BPF C. Required because gobee
emits `#include "vmlinux.h"` for CO-RE field access.

## Provenance

| Field | Value |
|---|---|
| Generated by | `bpftool btf dump file /sys/kernel/btf/vmlinux format c` |
| Source kernel | Linux 6.17.0-22-generic, Ubuntu 25.x, aarch64 (lima default VM) |
| Snapshot date | 2026-04-30 |
| Lines | ~200,000 |

## Regenerating

On any modern Linux box with `bpftool` installed:

```bash
sudo bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h
```

The dump reflects whatever kernel you ran it on. CO-RE handles cross-kernel portability at load time, so the .bpf.o produced from this header loads cleanly on other kernels too — provided the fields you actually read exist on the runtime kernel.

For a snapshot-based path (no live kernel needed), the [aquasecurity/btfhub-archive](https://github.com/aquasecurity/btfhub-archive) project keeps per-distro BTF dumps.

## Cross-arch note

This `vmlinux.h` is the aarch64 dump. If you're building for x86_64, regenerate inside an x86_64 VM/host. Future iterations may ship per-arch dumps under `vmlinux/{arm64,x86_64}.h` (the gecit pattern) and pick the right one via Makefile.
